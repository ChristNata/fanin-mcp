# Phase 5 Implementation Result — Token Benchmark + Generated README Figures

## Token measure chosen

Exact compact (no pretty) JSON-RPC payload UTF-8 byte length, then `bytes.div_ceil(4)` (stable 4-bytes-per-token ceiling).

Rationale:
- Deterministic and identical across runs, machines, and CI (no timestamps, no locale, no external state).
- Measures the actual bytes the server produces for `tools/list` (the 3 static meta-tools) and a representative session (discovery via `list_tools`, schema via `get_tool_schema`, invoke via `invoke_tool`, plus the request argument objects).
- No heavy tokenizer dependency (tiktoken etc.) — anti-stack policy preserved; rmcp stays at exact `=1.8.0`.
- Lightweight, reproducible, and clearly labeled as an estimate in the generated output and source.
- Matches the Phase 5 spec requirement for a "lightweight, deterministic, documented approximation" over the exact wire bytes.

Full definition and justification live in `benches/token_cost.rs` (comments + `token_estimate`).
